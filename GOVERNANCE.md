# Governance

Clean Development uses a maintainer-led model. Magrathean UK is the initial maintainer and is responsible for merge, release, and project-name decisions.

Technical proposals should be discussed in issues and pull requests. Changes affecting deletion behavior, ownership rules, configuration compatibility, licensing, or the stable CLI need clear review before merge. Use the private reporting route in [SECURITY.md](SECURITY.md) for security-sensitive matters.

Contributors may be invited to help maintain the project based on sustained, constructive work and sound judgment around destructive operations. Maintainers should disclose relevant conflicts and seek independent review of security-sensitive release changes when another maintainer is available.

If the initial maintainer becomes inactive, established maintainers may document a succession proposal publicly after reasonable attempts to contact them. The MIT License permits forks; it does not assign control of the original package or repository namespace.
