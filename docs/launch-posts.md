# Preparing a public announcement

Prepare an announcement only after checking the public repository, package availability, and named integration evidence. This document is a publication checklist, not proof of a launch.

## Facts to include

Explain that Clean Development routes new supported caches and Cargo build output into managed storage. Name only the adapters relevant to the example. Explain that setup alone leaves native integrations in skip mode and that a session choice enables routing.

Link the [repository](https://github.com/magrathean-uk/clean-development), [MIT License](../LICENSE), and [verification status](verification.md). Add an npm link only after checking the intended package and version in the registry.

Describe the boundary plainly: existing clutter is not migrated or deleted, prune requires explicit application and registered ownership, and routing is not a filesystem sandbox. Do not claim that every packaged host has passed acceptance or that billed tokens are unchanged.

## Demonstration

Use a disposable project and record the source or package version. Show the read-only session plan, a chosen routed command, its actual artifact destination, and sanitized status output. Keep account information, prompts, tokens, and private paths out of the recording.

Verify installation instructions against the published artifact before including them. Distinguish a CLI launcher from native GUI or lifecycle support.

## Publication

Check the destination community's current rules and any required disclosure or format on the day. Old weekly-thread links and prior moderation guidance are not reusable publication permission. State your affiliation and ask for one concrete kind of feedback, such as an adapter contract or a reproducible compatibility problem.

Keep publication separate from drafting. Do not post, submit, or send an announcement without authorization.
